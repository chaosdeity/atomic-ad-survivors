# Player-facing Language Rewrite Bible V0.1

상태: RECONSTRUCTION CANDIDATE / 플레이어 문장 편집 기준
적용 범위: 이번 03~06과 M01/M02의 신규 문안. 기존 문자열과 저장 필드는 바꾸지 않는다.

## 말하는 존재부터 구별한다

사람은 지금 필요한 것을 말한다. 기계는 자신이 맡은 일을 말한다. 목표 UI는 플레이어가 할 행동을 말한다. 기록은 누가 언제 무엇을 확인했는지 남긴다. 이 네 목소리를 같은 용어집으로 통일하지 않는다.

“호출을 보류했다”를 전부 “부름을 멈췄다”로 바꾸는 것이 목표가 아니다. 누가 누구를 왜 부르고 있었는지 장면 안에서 알아야 한다. 우편함 소리가 멈춘 것과 누군가의 생활이 보장된 것은 다른 결과다.

윤서가 어려운 말을 안다고 어려운 말만 하는 인물로 쓰지 않는다. 미나가 수량을 세는 사람이라고 매번 정산표처럼 말하게 하지 않는다. 인간인 퇴원 심사 대리, 반품 보류관, 회원 브로커도 예외가 아니다.

## 문맥별 대체 사전

기계/행정 칸은 실제 세계 안의 화면·인쇄물에서 필요한 경우에만 쓴다. 사람 말은 대사 후보, UI는 짧은 행동 안내, 기록 말은 새 일지 후보다. 아래 문안은 런타임 적용 승인이 아니다.

| 기계/행정 표현과 상황 | 사람 말 | 목표·선택 UI | 사람이 남기는 기록 |
|---|---|---|---|
| 호출: 우편함이 반복 안내함 | “받으러 오라는 소리가 계속 나.” | 우편함 안내 확인 | 우편함이 같은 안내를 반복했다. |
| 호출 보류: 안내를 멈춤 | “이 소리만 멈출게. 편지는 그대로 두고.” | 안내 멈추기 | 안내를 멈췄다. 받으러 올 사람은 확인하지 못했다. |
| 기존 대기 유지 | “누가 오면 들을 수 있게 놔둘게.” | 기다리는 안내 유지 | 안내를 켜 두었다. 누군가 돌아왔다는 뜻은 아니다. |
| 등록: 집에 이름이 남음 | “집에는 아직 그 사람이 사는 걸로 적혀 있어.” | 집에 적힌 이름 확인 | 이 집 기록에는 이전 이름이 남아 있다. |
| 등록: 환자라는 이유로 못 나감 | “몸은 나아도 여기선 아직 환자래.” | 퇴원 조건 읽기 | 현재 몸과 병원이 요구하는 조건을 따로 적었다. |
| 등록: 회원 혜택 | “그 사람 카드여야 문을 열어 줘.” | 입장 조건 확인 | 이 문은 특정 회원의 카드를 요구한다. |
| 판정: 가족 적합성 | “저 의자에 앉아야 식구라고 쳐 줘.” | 식탁의 요구 확인 | 식탁은 정해진 자리에 사람이 있는지 살핀다. |
| 판정: 정상 작동 | “움직이잖아. 저 기계가 싫어하는 방식으로.” | 고장과 복원 항목 비교 | 실제 고장과 되돌리라는 요구는 같지 않았다. |
| 판정: 통과 가능 | “문은 지나갈 수 있대. 배가 있는지는 몰라.” | 통과 뒤 안내 확인 | 통과 허가만 확인했다. 이후 이동은 확인하지 못했다. |
| 처리 완료: 배달 | “왔다는 건 써 놨는데, 누가 받았는지는 없어.” | 수령 기록 읽기 | 물건을 내려놓은 일과 사람이 받은 일을 구별할 근거가 부족하다. |
| 처리 완료: 반품 | “돌려보냈다고 끝난 건 아니잖아요.” | 받는 곳 확인 | 출발한 사실과 올바른 곳에 도착한 사실은 다르다. |
| 처리: 사람의 처지 | “그 사람은 지금 어디 있어?” | 당사자 만나기 | 사람을 만났는지부터 적는다. |
| 보류: 추가 판단을 미룸 | “지금은 못 정하겠어. 다시 물으러 올게.” | 다음 확인 남기기 | 다시 확인할 일과 그것을 맡을 사람을 적는다. |
| 보류: 상대를 기다리게 함 | “기다려 달라는 말은 했어. 언제까지인지는 안 말했고.” | 이전 약속 확인 | 당사자가 기다리는 동안 필요한 일을 확인한다. |
| 대상: 사람 | “저 안에 있는 사람.” | 병실의 사람 만나기 | 이름을 모르면 만난 장소와 당사자가 원하는 호칭을 쓴다. |
| 대상: 청소물 | “그 종이는 버릴 게 아니야.” | 메모를 치워 두기 | 내 메모도 바닥의 쓰레기와 함께 치워질 뻔했다. |
| 서비스: 주거 도움 | “문도 열어 주고 붕대도 줬어.” | 응급 키트 살피기 | 받은 도움의 종류와 실제로 쓴 것을 적는다. |
| 서비스: 식사 | “그 사람이 손을 떼면 밥이 안 나온대.” | 식사 조건 확인 | 누구의 손과 어느 식사가 연결되는지 현장에서 확인한다. |
| 서비스: 로봇 노동 | “지금은 못 도와줘. 나도 충전해야 해.” | 팝시의 부탁 듣기 | 팝시는 자기 충전 시간을 요구했다. |
| 프로세스 | “그다음엔 뭘 해야 문이 열려?” | 다음 행동 확인 | 문이 열리기 전에 실제로 요구한 행동을 적는다. |
| 상태 | “팔이 또 떨려?” | 팔의 움직임 확인 | 언제 어떤 움직임이 달라졌는지 적는다. |
| 검증 | “네가 직접 본 건 어디까지야?” | 두 기록 비교 | 직접 본 것과 기록이 주장한 것을 나눈다. |
| 접점 | “우편함 앞에서 만나.” | 우편함으로 이동 | 만난 장소를 평범한 지명이나 사물로 쓴다. |
| 노드 | “모델하우스 안쪽 장치.” | 모델하우스 조사 | 제작 ID가 아니라 실제로 본 위치를 적는다. |
| 권역 | “병원 쪽.” | 병원 구역 확인 | 이동한 지역의 플레이어 노출명을 쓴다. |
| 엔트리 | “맨 아래 줄을 봐.” | 마지막 항목 읽기 | 어느 기록의 어느 항목인지 적는다. |
| 플로우 | “먼저 문을 보고, 돌아와서 얘기하자.” | 조사 후 귀환 | 실제로 한 행동을 시간 순으로 남긴다. |
| 리소스·capacity | “침상은 비워도 밤에 지킬 사람이 없어.” | 지원할 수 있는 것 확인 | 물건, 자리, 돌볼 사람을 각각 적는다. |
| 동의 확보 | “같이 가고 싶은지 그 사람한테 물었어?” | 원하는 행동 묻기 | 상대가 고른 행동과 그 범위를 적는다. |
| 수령 책임 | “가져온 다음엔 누가 돌볼 건데?” | 맡을 일 정하기 | 받았다는 사실과 이후에 맡을 일을 구별한다. |
| 데이터 중복 | “같은 종이를 베꼈어. 사람까지 같다는 뜻은 아니고.” | 자료의 출처 비교 | 복제된 자료를 독립된 증거로 세지 않는다. |

같은 단어를 무조건 금지하는 방식도 피한다. 사람이 계약서를 읽어 주는 장면에는 문서의 표현을 인용할 수 있다. 다만 인용이 끝난 뒤 자기 요구는 자기 말로 해야 한다. 목표 UI에 ‘가족 구출 완료’처럼 확인하지 않은 성과를 넣는 일은 쉬운 말이어도 금지다.

## UI에서 지켜야 할 사실의 크기

M01의 선택 문안은 기존 두 의미와만 대응한다.

- 기존 `호출 보류` → 신규 노출 후보 `안내 멈추기`. 안내의 중단이지 사람 삭제·가족 해방·배달 취소가 아니다.
- 기존 `기존 대기 유지` → 신규 노출 후보 `기다리는 안내 유지`. 안내의 지속이지 도착 보증·구조 실패가 아니다.

원본 ID, 저장 값, 반복 보고 방지, 보상 조건은 바꾸지 않는다. 적용 전에 실제 문자열과 바인딩을 대조해야 한다. ‘잠깐 멈추기’처럼 자동 재개를 약속하는 문구도 넣지 않는다.

M02의 필수 목표는 세 기록을 읽고 보고하는 일이다. 메모를 구하는 연출이나 청소 흔적을 네 번째 필수 조사로 끼워 넣지 않는다. 미완료 귀환은 실패 엔딩이 아니다.

좋은 부분 귀환 문안:

윤서: “하나는 못 봤어.”

미나: “본 데까지 놓고 가. 나머지는 다음에 보자.”

이 대사만으로 저장 성공이나 보상 지급을 선언하지 않는다. 저장 실패는 실제 UI에서 명확하게 알린다.

## 화자별 목소리

### 윤서

먼저 장소나 행동을 짚는다. 불확실하면 모른다고 말하지만 그것으로 대화를 매번 닫지 않는다. 냉소는 상대를 이기는 재주가 아니라 피곤함이 새는 정도다.

“상자는 있었어. 다음 사람한테도 남아 있을지는 몰라.”

“내가 쓴 건 빼. 안 쓴 것처럼 세면 또 모자라.”

피할 것: 모든 대사의 마지막에 철학을 붙이기. 남들보다 정확한 말만 하는 인물로 만들기. 자기 부상과 실수를 정밀한 분석 뒤에 숨기기만 하고 비용을 치르지 않기.

### 미나

지금 필요한 답부터 묻는다. 화가 나면 문장이 짧아지지만 상대의 일을 구체적으로 요구한다. 말끝마다 숫자를 붙이지 않는다.

“그럼 오늘 뭘 꺼내 놓으면 돼?”

“네가 모르는 건 알겠어. 네가 맡을 건?”

“먹고 해. 그릇 위에 종이 올리지 말고.”

### 장도윤

손으로 확인하는 버릇이 있다. 아는 것을 자랑할 때도 공학 강의를 시작하지 않는다. 선의로 먼저 손대는 결함이 대사보다 빨리 드러난다.

“이 손잡이, 언제부터 뜨거웠어?”

“움직이게는 할 수 있어. 네가 싫어하는 소리까지 돌아올지는 봐야 하고.”

후반 변화: “열어 봐도 돼?”라고 먼저 묻고 실제로 기다린다.

### 팝시

처음에는 익숙한 환영 문구로 불편한 부탁을 감춘다. 그 문구가 재미있어도 계속 공연시키지 않는다. 자기 요구는 유아어가 아니라 짧은 보통말이다.

“즐거운 귀환을…… 이번에는 내 차례야. 충전기 비워 줘.”

“노래는 안 할게. 여기 있어도 되지?”

### 세븐

근거의 출처를 확인하는 질문을 한다. 기계답게 정확하려 하지만 ‘등록 상태 검증’처럼 내부 명세를 읊지 않는다. 오류를 인정할 때 사람의 수를 고쳤다는 식으로 말하지 않는다.

“셋 다 다른 곳에서 읽었습니까?”

“제가 센 것은 기록 셋입니다. 사람 셋은 아닙니다.”

### 복희

손대기 전에 묻는다. 경험을 말하되 격언을 연달아 내놓지 않는다. 보관하고 싶은 욕심 때문에 불편한 사람이 되기도 한다.

“접힌 데 펴도 되니?”

“안 읽을게. 없애도 된다는 말은 아직 못 들었어.”

### ROOM-12

처음에는 자기 부탁을 다른 사람의 필요로 돌려 말한다. 후반에는 원하는 행동을 자신을 주어로 말한다. 본명이나 성별을 대사로 새로 확정하지 않는다.

“저녁이 나오는 것까지만 보고 갈게요.”

“이사하려는 게 아니에요. 오늘 한 번, 밖에서 먹고 싶어요.”

### 인간인 지역 대립자

퇴원 심사 대리: “밖에서 받아 줄 사람이 없는데 문부터 열라고요?”

반품 보류관: “여기 두면 내가 지킵니다. 가져가면 누가 지키죠?”

회원 브로커: “받는 건 싫지 않으셨잖아요. 이름만 좀 빌려주시면 되는데.”

세 사람을 같은 냉정한 관료로 쓰지 않는다. 심사 대리는 돌봄을 내세워 막는다. 보류관은 책임질 사람이 없다는 사실로 압박한다. 브로커는 자신에게 유리한 거래를 자발적 선택처럼 꾸민다. 세 경우 모두 사람의 말이다.

### 비인간 장치

MAIL-LOOP는 반복이 핵심이다. 새로운 감정을 매번 덧붙이지 않는다. VAC-0는 위험물과 흔적의 차이를 처음부터 아는 귀여운 친구가 아니다. 가족심사 관리자는 처음 도움을 주었을 때와 같은 밝은 음성으로 사람을 묶는다.

기계 화면에는 `수령 완료`, `작업 범위 밖`, `이전 자료 유지` 같은 표현을 사용할 수 있다. 그 말이 현실의 전부라는 서술을 붙이지 않는다.

## 장면 단위 교정 예

### 보고를 서류 낭독에서 말다툼으로

제거할 방식: 미나가 ‘호출은?’이라고 묻고 윤서가 ‘보류했어’라고 답한다. 서로 아는 내부 항목만 오간다.

신규 방식:

미나가 남은 붕대를 집어 들었다.

“소리는?”

“멈췄어. 편지는 그대로 뒀고.”

“그럼 누가 받았는지는?”

윤서는 자기 팔에 감긴 붕대를 보았다.

“이건 내가 썼어. 나머지 사람 얘기까지 쓰진 마.”

기획어를 빼서 좋아진 것이 아니라, 지금 눈앞에 있는 물건과 보고의 범위가 충돌해서 장면이 된다.

### 설명 대신 잘못된 행동을 고치기

제거할 방식: ‘보존과 안전은 서로 다른 가치였다’고 서술자가 결론을 붙인다.

신규 방식: 윤서가 VAC-0 앞을 막는다. 메모는 남지만 바닥의 유리도 남는다. 싸우다 다시 그 자리에 발이 걸린다. 윤서는 메모를 식탁 위에 올리고 비켜선다. VAC-0는 바닥만 청소한다.

로봇이 갑자기 인간을 이해했다는 대사도, 윤서가 세계를 깨달았다는 해설도 필요하지 않다.

## 편집 완료조건과 검증

사람 대사의 `호출/등록/판정/처리/대상/프로세스/상태/검증/접점/노드/권역/엔트리/플로우/서비스/보류`는 문맥을 확인한다. 자동 치환하지 않는다. 이번 M01/M02의 신규 사람 대사에는 이 표현을 남기지 않는다. 제작 주석, 기존 명칭 인용, 기계 화면은 구별해 검사한다.

각 장면에서 독자가 답해야 할 것은 다섯 가지다. 어디인지, 누가 원하는지, 무엇이 막는지, 실제로 무엇을 했는지, 그래서 무엇이 달라졌는지. 하나라도 설명할 수 없으면 문장을 더 꾸미기 전에 사건부터 고친다.

낭독 시 대사만 이어 읽어 화자를 구별한다. 마지막 문장을 지워도 의미가 그대로라면 해설형 마무리인지 살핀다. 소품을 지웠을 때 사건이 그대로면 소품을 지우거나 실제 기능을 준다. 세계 전체의 진실을 한 장의 기록으로 확정하지 않는다.

검토 결과는 용어 수치만으로 보고하지 않는다. 문제 문장, 상황, 수정 문장, 수정으로 달라진 행동을 함께 남긴다. 실제 독자 낭독과 런타임 노출 검증은 후속 확인 항목이다.
