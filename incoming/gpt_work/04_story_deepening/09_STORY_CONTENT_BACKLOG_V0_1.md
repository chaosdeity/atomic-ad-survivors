## 1. 다음 작업의 결론

**먼저 현재 L01/L02의 실제 문자열과 이 패키지의 장면을 대조하고, 기존 접점에 들어갈 의뢰·조사·보고·재방문 문안을 확정한다.** 신규 NPC 배치나 시즌 전체 구현부터 시작하지 않는다.

지금 부족한 것은 장문의 새로운 설정이 아니다. 현재 두 의뢰에서 플레이어가 본 것과 추측한 것을 구분하고, 윤서와 미나가 무엇을 다르게 원하는지 느끼게 만드는 연결이다. P0는 기존 저장·전투·진행을 그대로 둔 문안과 반응의 개선을 우선한다.

이 문서는 모든 항목을 BACKLOG로 기록한다. 문서 작성 완료와 게임 적용 완료는 다르다. 새 사건과 관계 기억의 승인 여부는 D01–D09에서 확인한다.

## 2. P0 — 현재 게임에 바로 필요한 일

### ST-P0-01. 기존 문자열과 증거 역할의 일대일 대조

**WHY:** U34/U35는 기록의 존재와 진행을 확인하지만 세부 런타임 문자열 전체를 제공하지 않는다. 05의 E1/E2/E3를 이미 구현된 사실처럼 적용하면 정합성이 깨질 수 있다.

**DEPENDENCY:** 현재 브랜치 HEAD, PE01, U34/U35, 해당 의뢰·일지·오브젝트·선택·보고의 실제 문자열 읽기. D03의 증거 구분 방향.

**STORY VALUE:** 기존의 좋은 기록은 보존하고, 같은 정보를 반복하거나 사람 확인으로 과장된 문장만 고칠 수 있다.

**IMPLEMENTATION DEPENDENCY:** 후속 작업자는 실제 텍스트 소유 위치와 기존 상태 바인딩을 먼저 확인한다. 읽기만으로 확인 가능한 범위부터 수행하며, 이 작업 목록이 런타임 수정 허가는 아니다.

**DONE / VERIFY:** 현재 문장 → 증명하는 사실 → 제안 문장 → 바뀌지 않는 조건의 대응표가 생긴다. 출처 없는 인물·주소·관계·사건을 새로 넣지 않는다. 세 기록의 정확한 매핑이 불가능하면 그 부분은 HOLD로 남긴다.

**IMPLEMENTATION DEPENDENCY:** 현재 미나 접점만 우선 사용한다. 대화 선택지·무전·새 NPC 애니메이션·관계 점수를 전제로 하지 않는다.

**DONE / VERIFY:** L01 offer/report와 L02 offer/report가 각각 다른 부탁을 갖는다. 같은 ‘잘했다/다음 조사’ 문장으로 끝나지 않는다. 미완료 상태가 완료 보고 문안을 사용하지 않는다.

### ST-P0-03. 윤서의 관찰·자율 귀환 반응

**WHY:** 윤서의 좋은 프로필이 플레이어에게 설명되지 않은 채 머물 수 있다.

**IMPLEMENTATION DEPENDENCY:** 현재 가능한 텍스트 접점과 표시 길이를 확인한다. 전투 중 긴 독백, 필수 회상 컷신, 카메라 강제 연출을 추가하지 않는다.

### ST-P0-04. L01 두 선택의 범위와 보고 차이

**WHY:** 호출 처리와 가족 배정·구조 결과가 혼동되면 첫 질문이 잘못 닫힌다.

**WHY:** 독립적인 세 기록이 단순 수집 목록으로 읽히면 첫 사건의 확장이 약해진다.

**DONE / VERIFY:** 6개 조사 순서에서 아직 안 본 기록을 아는 문장이 없다. 청소 흔적 없이도 필수 의뢰와 핵심 질문이 성립한다. 흔적 하나로 VAC-0의 신원·의도를 확정하지 않는다.

### ST-P0-06. 미완료 귀환·보고 반복의 문안 분리

**WHY:** 부분 진행을 실제로 보존해도 대사가 전부 완료처럼 말하면 플레이어는 잘못된 결과를 기억한다.

**DEPENDENCY:** U34/U35의 현재 상태 계약, 04/05. 정확한 저장 필드는 후속 작업에서 확인한다.

**IMPLEMENTATION DEPENDENCY:** 현재 저장과 일회성 보상을 변경하지 않는다. 실패 시 rollback과 기존 슬롯을 보존하며, 테스트는 격리된 검증 조건으로 수행한다.

**DONE / VERIFY:** 부분 조사 후 귀환·재시작·후속 조사, 완료 보고, 이미 보고한 재대화에서 문안과 상태가 맞는다. 보상 중복이나 강제 완료가 없다.

### ST-P0-07. 재방문 payoff와 목소리 최종 편집

**WHY:** 같은 장소로 다시 가도 단순 텍스트 재생이면 서사 엔진이 멈춘다.

**DEPENDENCY:** ST-P0-02–06, 05 B10/B20, 08. D08 승인 전에는 기존 상태만 사용한다.

**STORY VALUE:** 처음에는 기다림으로 들렸던 호출, 새 증거처럼 보였던 반복 기록, 안전해 보였던 청소가 다르게 느껴진다.

**IMPLEMENTATION DEPENDENCY:** 새 방문 횟수·장면 소모·호감도 저장을 가정하지 않는다. 현재 상태로 반복 안전하게 말할 수 있는 문안을 우선한다.

**DONE / VERIFY:** 첫 방문과 재방문의 질문이 다르고 관찰 범위를 넘지 않는다. 화자를 가린 편집 검토에서 윤서/미나의 부탁이 구별된다. 실제 사용자에게 무엇을 새로 이해했는지 확인하며, 검증 전 재미 PASS를 붙이지 않는다.

## 5. 의존성과 작업 순서

권장 순서는 ST-P0-01 → ST-P0-02/03/04/05 → ST-P0-06/07이다. 문안 확정과 기존 동작의 회귀 검증을 묶고, 실제 문자열 매핑이 끝나지 않은 기록을 먼저 교체하지 않는다.

수량: P0 7개 / P1 6개 / P2 4개, 총 17개. 모두 후속 작업이며 이번 커밋에 코드·기존 문서 수정은 포함하지 않는다.

## 6. 후속 P0 작업자 전달용 실행 지시안

아래는 PM의 방향 결정과 별도 작업 범위 승인 후 사용할 지시안이다. 이 문서 자체로 런타임 수정·기존 story 교체·배포를 승인하지 않는다.

### 목표

Atomic Ad Survivors의 현재 L01/L02에서 기록의 주장과 실제 사람 확인을 구분하고, 윤서/미나의 욕망과 귀환 후 반응이 드러나는 P0 문안을 만든다. 새 설정의 양이 아니라 현재 두 의뢰의 체감을 개선한다.

### 작업 범위

ST-P0-01–07만 대상으로 한다. 실제 branch HEAD와 최신 PE01/U34/U35/전투 계약을 읽고, 의뢰·조사·일지·선택·보고의 현재 문자열 및 상태 바인딩을 확인한다. 승인된 작업 범위가 문안 설계뿐이면 현재 문장과 제안 문장의 차이, 대응 조건, 적용 의존성까지만 보고한다. 구현이 별도 승인된 경우에도 명시된 텍스트 접점 범위만 수정한다.

### 금지사항

Final Lock/Production Entry/graph/40 Local ID·name/기존 story 원본을 임의로 수정하지 않는다. 새 필수 기록·조사 순서 gate·timer·강제 첫 패배·보스·자동공격·관계 점수·저장 스키마·중복 보상 변경을 넣지 않는다. 실제 가족관계와 과거 대형 비밀을 확정하지 않는다. main 병합·배포는 별도 지시 없이는 하지 않는다.

### 완료조건

현재 문자열과 제안 문안의 매핑이 확인되고, 두 의뢰의 offer/report가 다른 부탁을 갖는다. L01 두 선택과 L02 세 기록의 여섯 순서, 선택 흔적 유무, 미완료 귀환과 이미 보고한 상태가 일관된다. 실제 문안에 없는 사실을 새로 확정하지 않으며, 구현 여부와 제안 상태를 분리한다.

### 테스트 또는 검증 방법

읽기만 승인된 작업이면 조건표·6순서·4조합·금지 의미 확장에 대한 문서 검증을 한다. 실제 적용까지 승인된 작업이면 기존 검증 방식을 유지하고 격리 조건에서 부분 귀환/저장/재시작/반복 보고를 회귀 확인한다. 사용자 저장을 완료 fixture로 덮어쓰지 않는다. 실제 플레이 증거 없이 재미나 전체 QA PASS를 선언하지 않는다.

### 결과 보고 형식

## 8. 전달 검증 기준

이번 패키지의 저장 범위는 `incoming/gpt_work/04_story_deepening/`의 지정된 10개 파일뿐이다. 단일 논리 commit을 우선하고, 저장 후 10개 경로를 해당 commit에서 다시 읽어 blob SHA와 내용을 확인한다. 부모 commit과의 비교에서 추가 10개·기존 수정 0·삭제 0이어야 한다.
